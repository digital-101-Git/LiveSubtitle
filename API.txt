LiveSubtitle Engine API v1 — Windows 앱과 미래 브라우저 확장 공용

구조
  Windows WPF UI → WASAPI 브라우저/시스템/마이크 오디오 → PCM16 WebSocket → Python 엔진
  Python 엔진 → 로컬 Whisper / Qwen3-ASR 또는 Gemini Live → 전사문
  전사문 → 로컬 llama.cpp / 선택한 GGUF → 선택 언어 caption 이벤트
  caption 이벤트 → Windows 투명 자막창 또는 향후 확장 오버레이

실행과 수명
- LiveSubtitle.exe는 필요한 경우 자식 Python 엔진을 자동 실행합니다.
- 주 창을 닫으면 트레이 상태로 엔진을 유지합니다.
- 앱을 완전히 종료하면 자신이 시작한 프로세스 트리를 종료합니다.
- 이미 별도로 실행된 엔진에는 연결만 하며 해당 외부 엔진을 종료하지 않습니다.
- 개발 시: runtime\python\python.exe engine\server.py --root <이 앱 폴더> --port 17865
- 이 버전은 한 번에 한 오디오 스트림을 처리합니다. 두 번째 클라이언트는 session_busy입니다.

주소/인증
  HTTP: http://127.0.0.1:17865
  WebSocket: ws://127.0.0.1:17865/v1/stream
- 서버는 loopback에만 바인딩합니다.
- GET /health만 공개하며 {ok:true, service:"LiveSubtitle", version:"1.0.2"}를 반환합니다.
- HTTP /v1/*는 Authorization: Bearer <token>이 필요합니다.
- 토큰은 첫 실행 시 config/engine-token.txt에 생성됩니다. 문서나 확장 소스에 넣지 마세요.
- 기본 임의 웹사이트 Origin은 거부합니다. Chromium extension Origin과 Origin 없는
  native client만 허용하며, 이 경우에도 토큰 인증이 필요합니다.
- HTTP 요청 본문은 64KiB로 제한합니다.
- 미래 확장은 host_permissions로 127.0.0.1을 요청하고 연결 토큰 입력/페어링 화면을
  구현해야 합니다. 이번 버전에 확장이나 자동 토큰 전달 기능은 포함하지 않았습니다.
- 오디오 업로드는 사용자가 해당 모드를 선택하고 시작한 세션에만 한정해야 합니다.

GET /v1/models
  {translation:[{name,path,size}], asr:[{name,path}]}
  path는 앱 루트 기준 상대 경로입니다.

GET /v1/settings
  {mode,language,target_language,translation_model,asr_model,asr_hints,qwen_boundary_recheck,gemini_key_set,save_gemini_key,status}
  mode: local | gemini
  language: auto | ko | en | zh | ja
  target_language: ko | en | zh | ja (기본 ko)
  asr_hints: string[] (기본 [])
  qwen_boundary_recheck: boolean (기본 false)
  API 키 자체는 응답하지 않습니다.
  status: {state,asr_ready,translation_ready,last_error,active_session}

PUT /v1/settings
  부분 설정 JSON. 위의 mode/language/target_language/모델 경로를 변경합니다.
  language를 ko/en/zh/ja로 지정하면 해당 언어를 전사와 번역의 입력 언어로 사용합니다.
  language가 auto, 빈 문자열, 공백 문자열, null이면 자동 감지를 사용합니다.
  language 필드를 생략하면 저장된 설정을 유지합니다. WS start에서도 같은 규칙입니다.
  target_language 생략=저장값, 빈 문자열/공백/null=한국어(ko)입니다. auto는 허용하지 않습니다.
  WS start와 HTTP 번역에서도 같은 규칙이며, 시작된 세션의 번역 언어는 끝날 때까지 고정됩니다.
  명시/감지된 원문 코드와 번역 언어가 같으면 원문을 그대로 표시합니다.
  asr_hints는 사용자가 입력한 인명·게임명 등 원어 용어이며 로컬 Qwen3-ASR에만 적용합니다.
  최대 32개, 항목당 48자, 정리된 항목 합계 512자입니다. NFC·앞뒤 공백 정리 후
  빈 항목과 정확히 같은 중복을 제거하며, 제어문자·모델 특수 토큰은 거부합니다.
  asr_hints 생략=기존 유지, []=비우기이며 null/문자열/비문자 항목은 400입니다.
  qwen_boundary_recheck는 로컬 Qwen의 강제 분할 구간을 뒤 음성과 한 번 재확인합니다.
  true/false만 허용하며 생략하면 저장값을 유지합니다. 기본은 꺼짐이며 필요할 때 true로 켭니다.
  켜면 지연이 늘 수 있습니다.
  4초 강제 경계의 첫 결과는 원문 미리보기로 내보내고, 같은 시작 PCM에 뒤 음성을
  최대 1초(또는 500ms 무음까지) 더해 한 번 재인식한 뒤 확정합니다. 자연 종료된
  짧은 발화는 기존대로 처리합니다. 재인식 오류/빈 결과는 첫 결과를 확정하고,
  추가 PCM은 다음 구간에서 다시 처리합니다. 재추론 시간이 추가되므로 총 지연이 1초라는 뜻은 아닙니다.
  두 옵션은 Whisper/Gemini에는 적용하지 않습니다. 힌트로 인식 정확도를 보장하지 않습니다.
  재확인을 켜는 예: {"asr_hints":["사용자가 정한 원어 용어"],"qwen_boundary_recheck":true}
  추가 쓰기 전용 항목: gemini_api_key, save_gemini_key(boolean, 기본 false)
  gemini_api_key 생략=기존 값 유지, 빈 문자열=메모리/저장 키 삭제
  save_gemini_key=false와 새 키=메모리 전용, true와 새 키=Windows CurrentUser DPAPI 저장
  스트림 처리 중에는 409 session_busy입니다.
  모델 경로는 models/translation 또는 models/asr 하위로 제한합니다.

POST /v1/models/import
  {path:"C:\\absolute\\model.gguf"}
  네이티브 앱용. 브라우저 Origin 요청은 거부합니다.
  models/translation으로 복사하며 기존의 다른 파일은 덮어쓰지 않습니다.

POST /v1/prepare
  현재 설정의 모델을 준비하고 {ok:true,ready:true,status:{...}}를 반환합니다.
  모델 로딩이 완료될 때까지 응답을 기다리므로 긴 클라이언트 타임아웃을 사용하세요.
  Gemini 모드는 키 존재 여부를 확인하지만 실제 Google 연결은 스트림 시작에서 합니다.

POST /v1/translate
  {text:"Hello",source_language:"en",target_language:"ko"} → {translation:"안녕하세요",target_language:"ko"}
  번역 모델을 먼저 준비해야 합니다. 최대 입력 6,000문자, 짧은 자막을 대상으로 합니다.
  출력 길이 초과/선택 언어 응답 실패는 명시적 오류를 반환합니다.

POST /v1/release
  현재 세션 중지 및 모델 해제. {ok:true,status:{...}}

POST /v1/logs/clear
  인증된 네이티브 앱 전용이며 Origin이 있는 브라우저 요청은 거부합니다.
  {ok:true,deleted_count:2,failed_files:[]} 형식으로 삭제 결과를 반환합니다.
  앱 logs 폴더의 직속 일반 파일만 삭제합니다. 하위 폴더·링크를 따라가지 않습니다.
  일부 파일 삭제 실패 시 ok:false와 failed_files 이름 목록을 반환합니다.
  세션과 모델은 유지합니다. 기존 대기 기록 처리→삭제→새 기록 저장 순서를 보장합니다.
  메모리의 이전 번역 기록도 비우고, 이미 지운 자막 ID의 교정은 기록을 되살리지 않습니다.
  이후 새 자막/엔진 출력이 발생하면 로그 파일이 다시 만들어집니다.

WebSocket 순서
1. 연결 후 10초 안에 첫 JSON 메시지:
   {"type":"auth","token":"<config/engine-token.txt 값>"}
2. 시작:
   {"type":"start","mode":"local","language":"en","target_language":"ko"}
3. status 이벤트를 받은 뒤 ready 이벤트를 기다립니다:
   {"type":"ready","session_id":"...","target_language":"ko"}
4. ready 이후 바이너리 프레임으로 raw PCM16LE, mono, 16,000Hz를 보냅니다.
   WAV 헤더 없이 100ms=3,200바이트 권장. 한 메시지 최대 32,000바이트.
   클라이언트 버퍼도 제한해야 하며 서버 오디오 대기량은 최대 6초입니다.
   대기량 초과 시 오래된 입력을 정리하고 세션을 유지합니다. 이때 일부 음성이 누락될 수 있습니다.
   클라이언트가 전송 전 PCM을 버렸다면, 다음 바이너리 프레임 바로 앞에 다음 JSON을 보내세요:
   {"type":"audio_gap","dropped_samples":1600}
   dropped_samples는 건너뛴 16kHz mono sample 수(바이트 수 아님), 1~57,600,000의 정수입니다.
   로컬 인식은 이전 입력과 이후 입력을 한 발화로 붙이지 않도록 인식 상태를 다시 연결합니다.
   Windows 앱은 전송 대기열에서 가장 오래된 패킷을 정리한 뒤 이 알림을 자동 전송합니다.
   Qwen3-ASR은 기존 PCMChunker로 20ms RMS 프레임(문턱값 0.002)을 처리합니다.
   시작 전 400ms를 보존하고 약 500ms 무음 또는 최대 4초에서 나눕니다.
   4초 상한의 강제 분할에는 마지막 200ms를 겹쳐 단어 경계를 보완합니다.
   클라이언트는 계속 같은 PCM 형식으로 전송하며 자체 VAD로 원음을 잘라낼 필요가 없습니다.
   인식기 자체의 비음성 검사는 별도로 유지되며 이 시간은 자막 표시 지연 보장이 아닙니다.
5. 이벤트 수신:
   {"type":"transcript","session_id":"...","segment_id":1,"text":"Hello","is_final":true}
   {"type":"caption","session_id":"...","segment_id":1,"source_text":"Hello",
    "text":"안녕하세요","language":"en","target_language":"ko","is_final":true,"revision":1,"translation_status":"ok"}
   Gemini의 안정된 완결 문장과 Whisper의 짧은 잠정 구절은 최종 확정 전에
   is_final:false로 먼저 번역할 수 있습니다.
   최종 전사에 따라 같은 session_id+segment_id의 caption을 교체합니다. 새 행으로 추가하지 마세요.
   동일 원문의 최종 확정은 기존 번역을 재사용합니다. source_text가 바뀌면 revision이 증가합니다.
   최종 전사에서 철회되거나 합쳐진 잠정 문장은 다음 이벤트로 삭제합니다:
   {"type":"caption_remove","session_id":"...","segment_id":1}
   UI는 해당 ID의 현재/대기/최근 자막을 삭제하고, 지나간 문장 교정으로 오버레이를 되감지 않습니다.
   transcript는 caption 큐에 그대로 추가하면 안 됩니다. preview:false는 번역 항목 갱신이며
   현재 인식 중인 원문 미리보기를 덮어쓰면 안 됩니다. 원시 중간 전사는 preview:true입니다.
   Whisper 중간 원문 인식은 preview:true로 표시합니다. 한국어 잠정 번역은 caption의
   is_final:false로 전달하며, 안정된 문장/절과 무음 뒤 남은 말은 is_final:true로 확정합니다.
   원문 transcript를 한국어 오버레이 자막으로 직접 표시하지 마세요.
   잠정 caption은 첫 음성 1.2초 이후부터 가능하며 원문 최대 96자, 최소 0.8초 간격입니다.
   Whisper에서 처음 번역할 짧은 미완성 구절은 두 번 동일하게 관측되고, 새 오디오와
   경과 시간이 각각 0.35초 이상 늘어나야 합니다. CJK 포함 시 문자·숫자 수 6자 이하,
   그 밖에는 2단어·24자 이하가 대상입니다. 명시적 문장/절 끝과 최종 확정은 대기하지 않습니다.
   이미 수락한 잠정 자막의 교정은 이 추가 조건을 거치지 않습니다. 첫 잠정 요청이 큐 혼잡으로
   거절된 뒤 원문이 바뀌면 안정성을 다시 확인하며, 재시도도 기존 갱신 간격을 따릅니다.
   확정 번역이 처리 중이거나 큐가 가득 차면 잠정 번역을 줄입니다.
   번역 대기열 6개가 가득 차면 최대 250ms 동안 짧은 혼잡 해소를 기다립니다. 계속 가득 차면
   가장 오래된 대기 번역을 정리합니다. 이때 확정 구절도 생략될 수 있으며,
   해당 구절과 그보다 오래된 처리 중 번역의 늦은 자막은 표시하지 않습니다.
   문장부호 없는 긴 발화는 안정된 약 3초 구절을 먼저 번역할 수 있으므로,
   is_final:true는 해당 자막 구절이 확정됐다는 뜻이며 전체 발화 종료를 뜻하지 않습니다.
   개별 문장의 한국어 출력/빈 출력/출력 길이 실패는 세션 전체를 중단하지 않습니다.
   해당 caption은 translation_status:"failed", text:"[번역하지 못했습니다]"가 되며
   source_text와 ID를 유지합니다. 이어서 type:"warning", code, message, segment_id가 옵니다.
   warning은 진행 기록에 남기고 계속 수신하세요. type:"error"와 구분해야 합니다.
   buffer_recovered는 입력/인식/번역 대기량 초과로 일부 구간을 건너뛰고 계속 처리한다는
   비치명 warning입니다. 최대 2초에 한 번 알리며 연결이나 세션을 종료하지 않습니다.
   버려진 인식 요청의 늦은 결과는 무시하고, 건너뛴 구간 앞뒤의 번역 문맥을 끊습니다.
   정리된 번역의 caption_remove도 처리해야 합니다. 개별 오류와 사용자 중지는 기존 정책입니다.
   복구 단계·건너뛴 양·직전 계산시간은 로컬 logs/stream-recovery.jsonl에 기록합니다.
   원문·번역·오디오·API 키를 포함하지 않으며 1MiB 파일과 이전 파일 1개로 제한됩니다.
   Whisper의 local_streaming_deadline 경고는 오래 정체된 구간을 마지막 인식 결과로
   처리했다는 뜻입니다. segment_id가 없는 세션 알림이며 수신/번역을 계속합니다.
   local_streaming_empty_final이 warning으로 오면 추가 오디오에서 대사를 인식하지
   못했다는 뜻이며, 다음 음성은 계속 처리합니다. 메시지 type으로 중단 여부를 구분하세요.
   local_streaming_pending_revised는 비어 있지 않은 새 인식 두 번이 이전 문맥만 반환하여
   잠정 꼬리를 확인하지 못했고, 그 오래된 잠정 문구의 복원을 철회했다는 비치명 알림입니다.
   segment_id 없는 세션 warning이며 이후 caption_remove로 철회된 잠정 ID를 처리합니다.
   이미 확정된 caption은 삭제하지 않습니다. 잠정 자막을 아직 보내지 않았다면 삭제 이벤트도
   없을 수 있습니다. 인식 결과 자체가 일시적으로 빈 경우의 복구와 구분합니다.
   잠정 번역이 실패해도 같은 원문의 최종 전사가 도착하면 다시 번역합니다.
   Whisper 잠정 번역의 출력 품질 실패는 기존 자막을 유지하며, 실패 caption/warning은
   확정 번역도 실패한 경우에 보냅니다. 모델/연결 오류에는 기존 오류 처리를 적용합니다.
6. 중지:
   {"type":"stop"} → {"type":"stopped","session_id":"..."}
   같은 연결에서 start를 다시 보내면 새로운 session_id가 발급됩니다.
   UI는 현재 session_id/세대에 속하지 않는 이전 결과를 표시하면 안 됩니다.

오류
  HTTP: {error:{code,message}} 또는 인증/요청형식 오류의 {detail:...}
  WebSocket: {type:"error",code,message}; 인증 실패/프로토콜 위반은 연결 종료 가능
  주요 code: session_busy, missing_api_key, model_missing, asr_load_failed,
  translation_not_ready, translation_language, translation_truncated, invalid_audio_gap,
  asr_timestamps, gemini_connect_failed, gemini_session_expiring
  비치명 warning code: local_streaming_deadline, local_streaming_empty_final,
  local_streaming_pending_revised, buffer_recovered. 위 WebSocket 이벤트 설명에 따라 계속 수신합니다.
