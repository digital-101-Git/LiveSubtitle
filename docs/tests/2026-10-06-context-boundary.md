# 같은 모델의 자동 문맥·음성 구간 경계 조정 시험

평가일: **2026-10-06** · NVIDIA GeForce RTX 4080 16GB

**두 후보 모두 미채택이며 앱 소스·기본값·모델은 유지했다.** 직전 원문을 자동으로 넣는 방법은 전체 문자 오류와 이전 문장 재출력이 증가했다. 음성 구간 경계를 조정하는 방법은 편집 오류가 1개 줄었지만, 원래 맞던 핵심 명사와 문장 의미를 훼손했다.

채택 조건은 **정확도 개선을 우선하고 현재보다 느려지지 않는 것**이다. 두 후보가 원문 품질 단계에서 탈락했으므로 번역 및 실시간 지연 시험으로 확대하지 않았다. 이번 결과는 시험한 두 정책에 대한 판단이며, 모든 문맥·분절 방법의 개선 가능성을 부정하는 결과는 아니다.

## A: 직전 확정 원문의 짧은 자동 문맥

### 방법

- 기존 요청 226개 중 원래 음성 필터를 통과한 194개 PCM을 동일하게 사용했다. 기준선과 후보를 교차 순서로 각 194회, 총 388회 인식했다.
- 현재 요청 전에 이미 확정된 **후보 자신의 직전 원문**만 사용했다. 기준선 결과나 참고 SRT를 문맥에 넣지 않았다. 원래 요청·확정 일정의 인과 관계도 확인했다.
- 직전 구간이 자연 종료했을 때 마지막 완성 문장 하나를 최대 32 tokenizer token 이내에서 사용했다. 강제 4초 종료, 입력 종료, 미완성 문장, 음성 겹침, 빈 결과, 3초를 넘는 PCM 간격은 제외했다. 긴 문장을 중간에서 자르지 않았다.
- 같은 구간의 선행 추론·최종 추론·캐시가 서로 다른 문맥을 보지 않도록 최초 요청에서 문맥을 고정했다.
- 실제 문맥 사용은 119/194회, 원시 결과 변경은 16/194회였다. 실행 오류는 없었다. 새 기준선 194개의 원문·언어·PCM 해시는 보존된 기준과 같았다.

### 결과와 미채택 이유

일부 표현은 참고 자막의 기대 의미에 가까워졌다. 예를 들어 `雪花`(눈송이)가 `循环`(순환)으로, `工资呗`가 `工资赔`(월급으로 배상한다는 표현)로 바뀌었다.

반면 짧은 감탄사를 인식하던 PCM에서 **직전 문맥 전체가 다시 출력**된 사례가 세 개 있었다. 예를 들어 `嗯。` 대신 이전 문맥의 `散会。`가 나왔다. 세 사례 모두 폐기된 잠정 결과가 아니라 최종 확정 원문에 포함됐다.

편집 오류는 기준선의 **치환 53 / 삭제 25 / 삽입 74**에서 후보의 **치환 51 / 삭제 23 / 삽입 100**으로 바뀌었다. 일부 치환·삭제 개선보다 삽입 증가가 컸고, 합계 오류가 22개 증가해 채택하지 않았다.

검사 한계도 남긴다. 시험용 문맥 필터가 tokenizer의 특수 토큰 전체를 처음부터 검사하지는 않았다. 실제 사용된 119개 문맥과 후보·기준 원문을 별도 점검한 결과 해당 제어 문자열은 없었으므로 이번 점수와 재출력의 원인은 아니었다. 이 시험용 필터는 제품에 반영하지 않았다.

고정된 요청·확정 일정을 사용한 품질 선별 시험이므로 실제 처리 지연이나 자동 언어 전환에서의 효과는 확인하지 않았다.

## B: 첫 인식 전 상대적으로 조용한 지점으로 경계 이동

### 방법

- 원래 최대 길이인 4초에서, 첫 인식 요청을 보내기 전에만 마지막 300 ms를 20 ms 프레임 단위로 검사했다.
- 전체 구간의 RMS 중앙값 절반 이하가 120 ms 이상 이어지는 부분 중 평균 에너지가 가장 낮은 구간을 선택했다. 동률이면 뒤쪽을 선택하고, 중점을 20 ms 단위로 내림해 경계로 삼았다.
- 조건에 맞는 부분이 없거나 이미 선행 추론이 시작됐다면 원래 경계를 유지했다. 이동한 PCM은 다음 구간에 보존하고 기존 200 ms 겹침도 유지했다.
- 옮길 부분에 기존 RMS 음성 판정을 통과한 프레임이 있어야 하며, 순수 무음 꼬리만 옮기지 않았다. 이미 판정한 음성은 다시 VAD로 거르지 않고, 기존 구간이 소유하던 짧은 음성도 최소 길이 때문에 버리지 않았다.
- 문자·언어·참고 SRT를 이용해 경계를 고르지 않았다.

### 실행과 검증

기준선과 후보 각각에 원본 PCM을 100 ms씩 공급하고 실제 Qwen 인식 결과를 즉시 확정 처리했다. **ASR 실행 중에는 가상 오디오 시계가 멈추는 순차 시험**이다. 후보가 만든 구간과 캐시·최종 결과는 평가하지만, 실제 재생 속도의 자막 지연이나 번역과의 GPU 공동 부하는 측정하지 않는다.

- 전사 경로 호출은 226회에서 227회로 늘었다. 여기에는 음성 필터에서 거절한 요청도 있으므로 GPU 생성 횟수와 같지 않다. 캐시 사용은 각각 2회였다.
- 최종 확정 이벤트는 220→221개, 정리된 원문 문장은 209→208개였다. 문장 개수 차이를 그대로 발화 누락 개수로 해석하지 않는다.
- 실제 경계 이동은 테스트 영상 0곳 / 샘플1 3곳 / 샘플2 5곳 / 샘플3 2곳으로 총 10곳이며, 이동량은 60–240 ms였다.
- 모든 요청 PCM이 원음의 해당 샘플 구간과 바이트 단위로 같았다. 캐시 출처, 최종 결과의 연결, 앞뒤 겹침을 확인했다. 새 기준선의 최종 원문 209개는 기존 실행과 동일했다.
- 후보 전용 CPU 검사 16개와 기존 controller/session 검사 62개를 통과했다. 네 입력 × 가상 추론 지연 0/0.3/0.8초의 12개 조건에서도 PCM·캐시 처리를 검사했다. 가짜 ASR을 사용하는 CPU 검사는 정확도 채점에 넣지 않았다.

10곳 모두 다음 구간으로 옮기는 PCM에 기존 RMS 음성 판정을 통과한 프레임이 있었다. 상대적으로 낮은 에너지는 실제 무음이나 단어 경계와 동일하지 않으며, 실제 120 ms 무음 10개를 찾았다는 뜻이 아니다.

### 결과와 미채택 이유

테스트 영상과 샘플1의 최종 원문은 그대로였다. 샘플2에서는 일부 중복이 줄었으나, 샘플2·3에서 다음과 같이 원래 맞던 표현이 손상됐다.

| 현재 인식 | 경계 조정 후 | 영향 |
| --- | --- | --- |
| `现在是我的私人时间。` | `现在是我的私人。` + `私人事情。` | 개인 시간이 사적인 일로 바뀌고 문장 조각이 중복됨 |
| `希望不是果酱。` | `希望不是国家。` | 잼이 국가로 바뀌어 핵심 명사 손상 |

샘플2는 44→43개 편집 오류, 샘플3은 29→29개였다. 샘플3에서는 참고 SRT에 없는 감탄사와 앞 문장 꼬리 감소가 새 명사 오류를 합계에서 상쇄했다. 참고 SRT에 없는 감탄사의 삭제를 무조건 정확도 개선으로 볼 수 없다.

편집 오류 1개 감소만으로 중요한 의미 회귀를 상쇄하지 않았다. 실제 지연이 나빠지지 않는지도 입증하지 못했으므로 현재 정책은 채택하지 않는다.

## 해석의 한계와 후속 판단

- 이번에 원음을 새로 청취하여 독립적인 정답을 만들지는 않았다. 참고 자막 밖 발화·감탄사·광고 꼬리와 동음 이름 표기 등의 불확실성이 있다. CER을 실제 발화의 음향 정답률이나 환각률로 바꾸어 부르지 않는다.
- 평가 자료는 중국어 네 입력이며 세 개는 같은 드라마다. 영어·일본어·게임·인터넷 방송 전반으로 일반화하지 않는다. 텍스트 정렬 점수는 정확한 음향 발화 시각이나 화면 표시 지연을 검증하지 않는다.
- 품질 단계에서 탈락해 HY-MT2 번역 및 실시간 지연 비교는 추가 실행하지 않았다. 따라서 번역 개선·속도 개선·속도 비악화를 주장하지 않는다.
- 결과를 본 뒤 문맥 길이, 저에너지 기준, 특정 단어 교정 규칙을 같은 네 영상에 반복해서 맞추지 않았다. 새로운 가설이나 독립 자료 없이 같은 정책을 다시 시험하지 않는다.
- 향후 시도에서는 전체 CER뿐 아니라 원래 맞던 핵심 의미의 회귀, 이전 문장 재출력, 원음 보존을 함께 확인한다.

## 보존 및 공개 범위

시험 완료 시 제품 엔진·설정·기록 101개 파일, 격리 기준선 110개 파일, 기존 모델·패키지·원음 226개 구간의 보존을 확인했다. 시험 당시 Git 추적 파일 변경은 없었으며 배포본도 변경하지 않았다. 별도 결과 검토와 평가기 CPU 검사 12개를 완료했다.

이 문서는 집계·방법·선별한 짧은 오류 사례를 공개한 시험 기록이다. 원본 영상·음성·전체 자막, 개인 설정·인증 정보, 원시 실행 로그와 내부 작업 경로는 포함하지 않는다. 원시 자료와 실험 실행기를 함께 공개한 재현 패키지는 아니다.
